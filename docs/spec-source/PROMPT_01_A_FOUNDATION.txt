【識別碼、格式與State】
ID使用非空不透明字串，不要用角色名稱構造玩家ID；seatNumber是1..12整數。
序列化資料只能是JSON值；缺值用明確null，不使用undefined、NaN、Infinity、function、Map、Set、Date實例。
時間是UTC ISO字串，來源由Clock port注入；順序以sequence判定。

Seat = {playerId, seatNumber, displayName, controllerType: HUMAN | NPC}。
必須驗證playerId唯一、seatNumber唯一且完整1..12，displayName去除前後空白後不可空白。
controllerType不影響身份分配與遊戲規則。

GameState必要欄位：
gameId, status, createdAtIso, lastSequence, lobby, manifest, lockedSetup, runtime, abortReason。
status在A-01只有LOBBY | LOCKED | ABORTED。

LOBBY：lobby={seats, rulesetDraft}；初始seats=[]；manifest、lockedSetup、runtime=null；abortReason=null。
LOCKED：lobby=null；manifest、lockedSetup有值；runtime=null；abortReason=null。
ABORTED：保留前一狀態的lobby/manifest/lockedSetup，runtime仍null；abortReason=HOST_REQUEST。

GameManifest：
gameId, dataSchemaVersion="1.0.0", engineContractVersion="1.0.0", engineBuildId,
createdAtIso, lockedAtIso, seatsSnapshot, rulesetSnapshot。
engineBuildId由application配置注入；測試固定值，不用reducer讀git或環境。

LockedSetup：
assignments: 每玩家一筆 {playerId, assignedRoleId, assignedFactionId, victoryBucket, assignedAtSequence}。
assignmentAudit: {randomAlgorithmId, privateSeed: string | null}。
Node正式adapter可用crypto.randomInt，privateSeed=null；測試可使用可重現的假RNG。
任何seed與assignments都屬SYSTEM_TRUTH，不公開。

manifest與lockedSetup從SetupLocked寫入後永久固定。abort不得改它們。
型別readonly只是第一層；還要schema檢查、輸入clone、不要返回可寫内部引用、必要的deep freeze與測試。

【A-01 Commands與可信身分】
對外傳入的command只能有：
commandId, gameId, actorPlayerId:null, commandType, payload, windowToken:null。
本次只有host命令；玩家階段在後續才做。

Command union：
CreateGame: payload={rulesetSnapshot}
ConfigureSeats: payload={seats}
LockGame: payload={}
AbortGame: payload={reason: HOST_REQUEST}

可信上下文TrustedPrincipal另外由內部入口提供：HOST(hostId)或PLAYER(playerId)。
四種A-01命令只有HOST可用；測試PLAYER被拒絕。
不得信任command payload偽造source=SYSTEM或principal；strict schema拒絕額外欄位。
這是內部授權契約測試，不代表已做網路驗證或帳號登入。

CreateGame：該gameId尚不存在；建立LOBBY。
ConfigureSeats：只能LOBBY；一次完整替換合法12席。
LockGame：只能LOBBY且已有合法12席；建立固定角色multiset並洗牌，按座號映射到playerId；一次SetupLocked事件鎖定manifest與assignments。
AbortGame：LOBBY/LOCKED可用，變ABORTED；ABORTED後除同ID重送外任何新命令拒絕。

【A-01 Event union】
只實作以下4種，不建立後續事件的空處理分支：
GameCreated payload={createdAtIso, rulesetDraft}
SeatsConfigured payload={seats}
SetupLocked payload={manifest, lockedSetup}
GameAborted payload={reason: HOST_REQUEST}

EventEnvelope：
eventId, gameId, sequence, eventType, eventVersion="1.0.0", transactionId,
causationCommandId, causedByEventIds:[], phaseId:null, recordedAtIso,
audience:{kind:SYSTEM_TRUTH}, payload。

A-01全部事件均視為truth stream，不做公開端點。不要因Seats看似公開就暴露原始log。
sequence自1起連續，每局不得重複。eventId同局唯一。
SetupLocked的assignedAtSequence必須等於自身事件sequence。

所有schema使用strict物件，unknown input先parse才進domain；未知eventType、eventVersion、欄位或非法轉移須失敗，不可忽略。
用discriminated union與窮盡檢查，不能default: return state吞掉未知事件。

【純Reducer與重播】
提供等價函式：reduceEvent(state: GameState | null, event) → 新GameState，replay(events) → GameState。
初始state=null，只能接GameCreated。
驗證gameId、sequence、事件版本、階段轉移、所有座位和角色分配及鎖定不變條件。
不修改傳入state/event；不重新抽牌、不讀當前時間、不使用Math.random、不呼叫外部服務。
replay無事件明確回無遊戲狀態，不虛構gameId。

【Random、Clock、ID ports】
RNG port提供randomInt(exclusiveUpperBound)與algorithmId/privateSeed audit。
使用正確界限的Fisher–Yates洗牌；validate隨機源輸出為合法整數，非法時整筆LockGame失敗。
production adapter採Node crypto.randomInt；測試注入固定序列RNG，不要求測試隨機結果碰巧不同。
role RNG不與未來public order或NPC randomness混用。
reducer/replay永不呼叫任何port。ID及timestamp在事件建立時由application決定。

【Repository與冪等】
使用InMemoryGameRepository；可操作多個gameId，彼此隔離。
Repository內部保存events及成功command receipts，不以state當唯一真相。

CommandReceipt = {
commandId, gameId, principalKey, canonicalRequest,
firstSequence, lastSequence, outcomeCode
}。
outcomeCode對應GAME_CREATED / SEATS_CONFIGURED / SETUP_LOCKED / GAME_ABORTED。
canonicalRequest是可比較的已驗證請求表示，物件鍵順序不同不應造成誤判。

處理順序：驗證trusted principal → 找receipt → 同ID同內容回原receipt → 同ID不同內容拒絕 → 載入state → 驗證業務規則 → 建立事件 → 原子append。
只有成功請求需要receipt；失敗命令不得新增domain event。

append(expectedSequence, eventsBatch, receipt)必須全部成功或全部失敗。
先完整驗證到暫存副本，才替換store內容。若sequence、schema或receipt任一錯誤，原store不得變。
同commandId同內容重送，即使state之後已前進，也回原成功receipt；不重抽角色、不新增event。
相同commandId不同payload或不同principal，拒絕COMMAND_ID_REUSED。
兩個寫入使用同expectedSequence，最多一個不同操作能成功；另一個回CONCURRENCY_CONFLICT。
不要把同commandId重送與不同commandId重複LockGame混為一談；後者应回GAME_ALREADY_LOCKED。

【匯出匯入】
exportBundle(gameId) → JSON string。
importBundle(json) → 新的或指定空gameId的repository資料；不得覆寫已有局。
格式：{formatVersion:"1.0.0", gameId, events, commandReceipts}。
不把snapshot當必要項。匯入要完整parse、驗證、重播到暫存，再一次保存。
檢查events的gameId、連續sequence、eventId唯一、合法state transition、receipt對應command與sequence範圍。
檢查receipt principal與canonicalRequest形狀；receipt範圍涵蓋的事件causationCommandId必須相符，不得跨到別人的交易。
每個成功command transaction必須有對應receipt；禁止重複receipt commandId。A-01每command恰有一個事件。
receipt中的commandType必須對應正確事件類型；CreateGame/ConfigureSeats/AbortGame的canonicalRequest payload須與事件內容相符，LockGame只允許空payload。

匯入後重送已成功的LockGame，仍需回原receipt，不新增事件。
明確標示export是開發／truth備份格式，不是普通玩家或觀戰API。
記憶體+手動JSON恢復不等於已完成自動持久化；README不可宣稱已可抗當機自動恢復。
